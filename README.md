# Лабораторна робота №2

## Діагностика продуктивності JVM у VisualVM

Проєкт містить демонстраційний Java-додаток `Main`, який створює:

- постійне CPU-навантаження у потоці `cpu-worker`;
- короткоживучі об'єкти для спостереження за GC;
- контрольоване утримання блоків пам'яті для аналізу heap;
- кілька потоків у різних станах.

## Запуск

Потрібен JDK 11 або новіший.

### Швидкий запуск для демонстрації

У PowerShell, відкритому в корені проєкту, виконайте:

```powershell
.\run-lab.ps1
```

Скрипт скомпілює `Main.java`, запустить Java-додаток і відкриє VisualVM на сумісному JDK 17. У VisualVM відкрийте **Local** і двічі клацніть процес **Main**.

Після завершення демонстрації виконайте:

```powershell
.\stop-lab.ps1
```

Скрипт зупинить тільки лабораторний процес і VisualVM.

```powershell
New-Item -ItemType Directory -Force out
javac -d out src\Main.java
java -Xms128m -Xmx512m -XX:+UseG1GC -cp out Main
```

Програма виведе PID процесу. Не закривайте термінал під час дослідження.

## Робота у VisualVM

1. Запустіть програму та запам'ятайте PID.
2. Відкрийте VisualVM і виберіть локальний процес `Main`.
3. На вкладці **Monitor** спостерігайте CPU, Heap, Metaspace, кількість потоків і GC activity.
4. На вкладці **Threads** перевірте стани `RUNNABLE`, `TIMED_WAITING` та `TERMINATED`; виконайте `Thread Dump`.
5. У **Sampler > CPU** натисніть **CPU Sample** і знайдіть `runCpuWork` та математичні функції як найважчі методи.
6. У **Sampler > Memory** натисніть **Memory Sample**; очікувано часто створюються масиви `byte[]`, `ArrayList` та об'єкти потоків.
7. За потреби відкрийте **Heap Dump**, перегляньте класи за кількістю екземплярів і виконайте порівняння після GC.
8. Зупиніть програму клавішами `Ctrl+C`.
